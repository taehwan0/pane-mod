# pane-mod

한국어 | [English](README.en.md)

Claude Code의 HUD를 오른쪽 pane에 그리는 mod입니다. 모델과 사용량, 컨텍스트, Claude의 작업, 서브에이전트, 작업 로그를 보여 주고, 좋아하는 캐릭터를 스프라이트로 지정하면 세션 상태에 맞춰 움직입니다.

![질문을 보내면 pane의 스프라이트가 working 동작으로 바뀌고, 답이 끝나면 idle 동작으로 돌아오며 log 카드에 그 턴이 한 줄 남는 모습](docs/demo.gif)

## 빠른 시작

```sh
claude plugin marketplace add taehwan0/pane-mod
claude plugin install pane-mod@pane-mod
```

Claude Code를 다시 시작하면 HUD가 나타납니다. 전체 화면 보기에서는 오른쪽 pane에, 그 밖에서는 입력창 위에 그립니다.

스프라이트를 쓰려면 캐릭터의 idle·working 프레임(PNG)을 폴더에 넣고 그 폴더를 지정합니다.

```text
~/.config/pane-mod/my-character/
├── idle/     frame_001.png …    # 턴 사이
├── working/  frame_001.png …    # 모델 턴 진행 중
└── sounds/   idle/  working/    # 상태별 소리 (선택)
```

```sh
echo '{"spriteDir":"/Users/me/.config/pane-mod/my-character","soundDir":"/Users/me/.config/pane-mod/my-character/sounds"}' \
  | claude plugin configure pane-mod@pane-mod --values-stdin
```

- `/pane-mod`로 pane을 열고, `/pane-mod auto|band|pane|hint`로 이번 세션의 레이아웃을 바꿉니다.
- Claude Code 2.1.292 이상이 필요합니다. 스프라이트는 Ghostty와 cmux에서 확인했고, Orca(1.4.221)에서는 그려지지 않습니다.
- 데모의 캐릭터는 예시입니다(아래 "라이선스" 참고).
- 설정 항목, 문제 해결, AI에게 설치를 맡기는 방법은 [INSTALL.md](INSTALL.md)에 있습니다.

## 만든 이유

27인치와 32인치 모니터를 주로 쓰면서, 보조 정보는 왼쪽이나 오른쪽 패널에 두고 가운데의 주 작업 영역을 넓게 쓰는 배치를 좋아하게 되었습니다. Arc, Zen, Dia 같은 세로 탭 브라우저를 즐겨 쓴 것도 같은 이유였습니다. Claude Code의 HUD 정보는 늘 필요하지만, 입력창 위아래에 두면 프롬프트와 응답이 나오는 영역이 그만큼 줄어듭니다. 그래서 늘 옆으로 치우고 싶었고, Claude Code가 mod로 옆 pane을 지원하게 되면서 그 정보를 오른쪽으로 옮겼습니다.

## 화면 구성

HUD가 그리는 내용을 글자로 옮긴 도식입니다.

```
  [sprite]  my-app(refactor/search)
  [ 10×5 ]   Opus 5.5  ▰▰▰▰▱ xhigh · $1.50                         (모델은 반전 배지)
  [      ]  ctx ▰▰▰▰▱▱▱▱▱▱ 42% · 5h ▰▰▰▰▰▰▰▱▱▱ 70% ↻2h05m · 7d ▰▱▱▱▱▱▱▱▱▱ 12% ↻3d0h
  [      ]  context 3 md (Project 2 · User 1) · hooks 3 · tools 2 · MCP 3/2srv · skills 12 · cmds 30
  [      ]  mode auto ·  ● WORKING  1m08s  ▶ Bash git status · turns 12 · style explanatory
            ↳ ● Explore  find the login bug  · 1m12s · 14 tools · Grep
```

```

╰──────────────────────────────────────────────────╯

╰──────────────────────────────────────────────────╯
  이어서 tasks, subagents, context, recent, log 카드 (기본 순서, paneOrder로 바꿈. 내용이 있고 설정이 켜져 있을 때만)
```

## 요구 사항

- Claude Code 2.1.292 이상에서 만들고 시험했습니다. mod(`hooks/hooks.json`의 `modules`)를 지원하는 버전이어야 합니다.
- 스프라이트는 Claude Code가 그림을 그릴 수 있다고 판단한 터미널에서만 보입니다. Claude Code는 kitty graphics protocol의 유니코드 placeholder 방식으로 그림을 그리므로, 이 방식을 지원하는 터미널이어야 합니다. Ghostty와 cmux에서 동작하는 것을 확인했습니다. 공식 문서에 따르면 kitty 0.28 이상에서도 그려집니다.
- **Orca에서는 현재 버전(1.4.221) 기준으로 스프라이트가 보이지 않습니다.** Orca의 터미널(xterm.js)은 kitty 이미지를 직접 배치하는 방식은 그리지만, 유니코드 placeholder를 지원하지 않고 kitty 그래픽 지원 질의에도 응답하지 않습니다. Claude Code는 이런 터미널에서 그림 대신 `alt`를 그립니다. 이때 pane-mod는 이를 감지해서 스프라이트 자리와 여백을 없애고 글자 정보만 표시합니다.
- 빌드 단계는 없습니다. Claude Code가 `hooks/register.tsx`를 그대로 읽어서 실행합니다.
- 스프라이트 프레임과 소리 파일은 함께 배포하지 않습니다. 지정하지 않으면 스프라이트 자리와 소리를 생략하고 글자 HUD만 표시하며, 오류는 나지 않습니다. 직접 준비한 폴더는 `spriteDir`, `soundDir` 설정으로 지정합니다(아래 "스프라이트와 소리 파일" 참고).

## 설치

설치 명령은 위의 "빠른 시작"에 있고, 설치 중에 정할 설정과 확인 방법, 문제 해결은 [INSTALL.md](INSTALL.md)에 있습니다. 이 저장소 자체가 마켓플레이스(`.claude-plugin/marketplace.json`)입니다.

저장소를 clone했다면 그 폴더를 마켓플레이스로 등록할 수도 있습니다(`claude plugin marketplace add ~/work/pane-mod`). 이 경우 파일을 고친 뒤 실행 중인 세션에서 `/reload-plugins`를 입력하면 바로 다시 읽습니다. 설치하지 않고 한 세션에서만 써 보려면 다음과 같이 실행합니다.

```
claude --plugin-dir ~/work/pane-mod
```

### statusLine과 함께 쓸 때

mod는 `statusLine` 영역에 그릴 수 없습니다. 그래서 HUD는 오른쪽 pane이나 입력창 위(band)에 그려집니다. 기존 statusLine HUD를 대체하려면 `~/.claude/settings.json`에서 `statusLine` 항목을 직접 지워야 합니다. mod가 설정 파일을 바꾸지는 않습니다.

## 설정

설정은 처음 설치할 때 고르고(INSTALL.md 2장), 설치한 뒤에는 아래 "설정 바꾸기"의 방법으로 바꿉니다.

| 키 | 기본값 | 설명 |
|---|---|---|
| `layout` | `auto` | HUD를 그리는 위치입니다. `auto`는 화면이 pane을 옆에 붙일 수 있으면(전체 화면 보기, 충분한 폭) 오른쪽 pane에 상세 HUD를 그리고 band에는 한 줄 요약만 둡니다. 그렇지 않으면 band에 5행 HUD를 그립니다. `band`는 band만, `pane`은 항상 pane을 씁니다. `hint`는 band와 pane을 그리지 않고, 입력창 아래 힌트 줄의 끝에 한 줄 정보를 붙입니다(아래 "힌트 줄 레이아웃" 참고). 세션 안에서는 `/pane-mod auto`, `/pane-mod band`, `/pane-mod pane`, `/pane-mod hint`로 바꿉니다. |
| `animate` | `true` | 스프라이트 애니메이션입니다. 끄면 각 동작의 첫 프레임에 머뭅니다. |
| `sprite` | `true` | 스프라이트 표시 여부입니다. 끄면 글자 정보만 표시합니다. 켜 두어도 스프라이트 폴더에 프레임이 없으면 스프라이트를 생략합니다. |
| `bandWithPane` | `off` | pane이 보이는 동안 band에 그릴 내용입니다. `off`는 아무것도 그리지 않고(pane이 모든 정보를 보여 줌), `line`은 한 줄 요약을 그립니다. |
| `alerts` | `true` | 승인 창 아래에 한 줄을 붙여, 언제부터 기다렸는지와 떠 있는 한도 경고(context·5h 80%·90%, 리셋 전 5h 도달 예측)를 적습니다. toast나 소리로 부르지는 않습니다(아래 "알림" 참고). |
| `sound` | `true` | 상태가 바뀔 때 소리 폴더의 `<상태>/`에서 소리 하나를 무작위로 재생합니다. 상태는 `working`(모델 턴 시작)과 `idle`(턴 종료)입니다. 새 소리가 시작되면 재생 중이던 소리를 멈춥니다. 폴더에 소리 파일이 없는 상태에서는 아무 소리도 내지 않습니다. macOS에서는 `afplay`로 재생하고, 다른 시스템에서는 소리가 나지 않습니다. |
| `agents` | `summary` | 서브에이전트 표시 방식입니다. `summary`는 상태별 개수 한 줄, `list`는 에이전트마다 한 줄, `off`는 표시하지 않습니다. |
| `showSession` | `true` | pane 첫 카드의 session 행(프로젝트, branch, 모드, 턴 수, 스타일)과 band 1행을 표시합니다. 꺼도 `/rename`으로 지정한 세션 이름은 첫 카드에 남습니다. |
| `showNow` | `true` | pane 첫 카드의 now 행(작업 상태 배지와 경과 시간, 지금 실행 중인 도구)과 band의 상태 행을 표시합니다. |
| `showTasks` | `true` | tasks 카드(Claude의 작업 목록)를 pane에 표시합니다. |
| `showModel` | `true` | 모델 카드의 첫 행(모델, effort 게이지)과 band 2행을 표시합니다. totals가 꺼져 있으면 비용도 여기에 표시합니다. |
| `showUsage` | `true` | 모델 카드의 게이지(context, 5h와 pace, 7d)와 band 3행을 표시합니다. |
| `showTotals` | `true` | 모델 카드의 비용 행(세션 비용)과 토큰 행(입력·출력 토큰, 캐시 적중률)을 표시합니다. |
| `showContext` | `false` | context 카드(md 파일, hooks, 도구, MCP, skills, commands)와 band 4행을 표시합니다. 세션 중에 거의 바뀌지 않으므로 기본으로 꺼 둡니다. |
| `showRecent` | `true` | recent 카드(이 세션에서 최근에 쓴 skill과 MCP 도구)를 pane에 표시합니다. 쓴 것이 없으면 켜 두어도 카드를 그리지 않습니다. |
| `showLog` | `true` | log 카드(작업 로그, 상세, 파일 열기)를 pane에 표시합니다. |
| `logTurns` | `50` | 세션마다 보관하는 최근 턴 수입니다. 넘으면 오래된 턴부터 지웁니다. `0`이면 모든 턴을 보관하고, 1부터 4까지는 5로 처리합니다(아래 "로그 보관" 참고). |
| `logSessions` | `30` | 로그를 보관하는 세션 수입니다. 가장 최근에 저장한 세션부터 남깁니다. `0`이면 세션 수를 제한하지 않습니다. |
| `logDays` | `14` | 마지막으로 저장한 뒤 로그를 보관하는 날수입니다. 이 기간이 지나면 그 세션의 로그 파일을 지웁니다. `0`이면 기간을 제한하지 않습니다. |
| `paneOrder` | `tasks,agents,context,recent,log` | pane에서 첫 카드와 모델 카드 아래에 놓는 카드의 순서입니다. `tasks`, `agents`, `context`, `recent`, `log`를 쉼표나 공백으로 구분해서 적고, 대소문자는 가리지 않습니다. 모르는 이름과 중복된 이름은 무시하고, 적지 않은 카드는 기본 순서대로 뒤에 붙입니다. 그래서 순서를 바꿔도 카드가 사라지지 않으며, 카드를 숨길 때는 `show…` 설정을 씁니다. `log`를 마지막에 두지 않으면 휠로 로그를 넘길 수 없습니다(아래 "로그 스크롤" 참고). |
| `sessionColor` | `auto` | pane 첫 카드의 테두리와 세션 이름의 색입니다. `auto`는 `/color`로 고른 색을 쓰고, 고른 색이 없으면 테두리를 흐린 노랑으로 칠합니다. 테마 키나 `#rrggbb` 형식의 색을 적으면 `/color`와 관계없이 그 색으로 고정합니다. 올바르지 않은 값은 `auto`로 처리합니다. |
| `modelColor` | `claude` | 모델 카드의 테두리 색입니다. 테마 키나 `#rrggbb` 형식의 색을 적으며, 올바르지 않은 값은 `claude`(Claude 주황)로 처리합니다. |
| `cardColor` | `subtle` | 나머지 카드(tasks, subagents, context, recent, log)의 테두리 색입니다. 테마 키나 `#rrggbb` 형식의 색을 적으며, 올바르지 않은 값은 `subtle`(테마의 회색)로 처리합니다. |
| `barFilled` | `▰` | 모든 게이지(effort, ctx, 5h, 7d)에서 채워진 칸을 그리는 문자입니다. 폭이 한 칸인 문자 하나여야 하며, 이모지, 전각 문자, 공백, 제어 문자, 결합 문자는 받지 않습니다. 올바르지 않은 값은 기본값으로 처리합니다. |
| `barEmpty` | `▱` | 모든 게이지에서 빈칸을 그리는 문자입니다. 조건은 `barFilled`와 같으며, 올바르지 않은 값은 기본값으로 처리합니다. |
| `spriteSource` | `auto` | 스프라이트 프레임을 터미널에 보내는 방식입니다. `auto`는 Ghostty와 kitty에는 PNG 파일 경로를, 그 밖의 터미널에는 PNG 데이터를 보냅니다. 파일 경로가 거부되면 그때부터 데이터로 보냅니다. `file`과 `bytes`로 고정할 수도 있습니다. |
| `spriteDir` | (빈 값) | 직접 준비한 스프라이트 폴더입니다. 비워 두면 플러그인 폴더의 `assets/`를 찾습니다(저장소에는 들어 있지 않습니다). 폴더 구조는 아래 "스프라이트와 소리 파일"에 있습니다. |
| `soundDir` | (빈 값) | 직접 준비한 소리 폴더입니다. 비워 두면 플러그인 폴더의 `assets/sounds/`를 찾습니다(저장소에는 들어 있지 않습니다). |

색 설정(`sessionColor`, `modelColor`, `cardColor`)에는 `#rrggbb` 형식의 색이나 Claude Code의 테마 키를 적습니다. 테마 키로 적은 색은 사용자가 고른 테마(다크, 라이트 등)에 맞게 그려지며, 대소문자는 가리지 않습니다. 쓸 수 있는 테마 키는 `text`, `inverseText`, `inactive`, `subtle`, `suggestion`, `remember`, `success`, `error`, `warning`, `merged`, `claude`, `permission`, `planMode`, `autoAccept`, `promptBorder`, `bashBorder`, `ide`, `diffAdded`, `diffRemoved`, `diffAddedDimmed`, `diffRemovedDimmed`, `diffAddedWord`, `diffRemovedWord`입니다. 게이지의 채워진 칸 색(사용률에 따른 초록, 노랑, 빨강)과 ` ● WORKING ` 배지의 색은 바꿀 수 없습니다.

### 설정 바꾸기

설정을 바꾸는 별도의 명령은 없습니다. 모든 설정은 Claude Code의 플러그인 설정(`userConfig`)에 저장되며, 다음 방법 중 하나로 바꿉니다.

| 방법 | 하는 일 | 적용 시점 |
|---|---|---|
| 입력창에 `/plugin configure pane-mod@pane-mod` | 모든 항목을 설정 화면에서 바꿉니다. | 저장하면 Claude Code가 mod를 새 값으로 다시 로드합니다. |
| 입력창에 `/config` | 설정 목록의 pane-mod 행에서 한 항목씩 바꿉니다. | 같음 |
| Claude에게 요청 | "context 섹션 보이게 해 줘", "소리 꺼 줘"처럼 말하면, Claude가 [AGENTS.md](AGENTS.md)의 "설정 변경을 요청받았을 때" 절차에 따라 아래 셸 명령으로 값을 바꾸거나 입력할 명령을 안내합니다. | 아래 셸 명령과 같음 |
| 셸에서 `claude plugin configure` | 아래 예시처럼 현재 값을 확인하고, 바꿀 값만 JSON으로 넘깁니다. | 실행 중인 세션에서는 `/reload-plugins`를 입력합니다. 반영되지 않으면 Claude Code를 다시 시작합니다. |

```sh
# 현재 값 확인 (inputs: 기본값까지 반영된 현재 값, choices: 고를 수 있는 값)
claude plugin configure pane-mod@pane-mod --json

# 바꿀 값만 저장 (값은 문자열로 적고, spriteDir·soundDir를 ""로 두면 기본 폴더로 돌아감)
echo '{"showContext":"true","agents":"list"}' | claude plugin configure pane-mod@pane-mod --values-stdin
```

- 허용되지 않는 값을 넘기면 저장하지 않고 `must be one of: …`처럼 이유를 알려 줍니다.
- `paneOrder`, 색 설정, 게이지 문자처럼 직접 적는 값은 CLI가 검사하지 않습니다. 대신 mod가 값을 읽을 때 올바르지 않은 부분을 기본값으로 바꾸므로, 값을 잘못 적어도 HUD가 그려지지 않는 일은 없습니다.
- `spriteDir`, `soundDir`에 없는 폴더를 넣어도 저장은 되지만, 그 경우 스프라이트나 소리가 생략됩니다.
- 이번 세션에서만 레이아웃을 바꾸려면 `/pane-mod auto`, `/pane-mod band`, `/pane-mod pane`, `/pane-mod hint`를 씁니다. 이 명령은 설정을 저장하지 않습니다.
- `~/.claude/settings.json`을 직접 고치지 않는 것을 권장합니다. 위 방법은 값을 검사한 뒤에 저장합니다.

## 레이아웃: band와 pane

| 상황 (`layout: auto`) | 동작 |
|---|---|
| 전체 화면 보기, 폭 충분 | 오른쪽에 pane(요청 폭 56칸)을 붙입니다. pane에는 pane 폭 전체를 쓰는 첫 카드에 세션·진행 중인 턴과 오른쪽의 작은 스프라이트(12×6칸)를 함께 담고, 그 아래에 모델 카드(모델, effort, 사용량, 비용), tasks, subagents, context, recent, log 카드를 차례로 그립니다. 모델 카드 아래 카드의 순서는 `paneOrder`로 바꿀 수 있습니다. 카드는 둥근 테두리(`Box`의 `borderStyle: 'round'`)로 관심사를 묶으며, 테두리 색은 `sessionColor`, `modelColor`, `cardColor`로 바꿉니다. 내용이 없거나 설정이 꺼진 카드는 그리지 않습니다. 폭이 좁으면 잘라 내지 않고 줄을 바꿉니다. band는 기본으로 비워 두고, `bandWithPane: line`이면 한 줄 요약(`━━  모델  effort · ctx · 5h ·  ● WORKING  경과 시간 · 서브에이전트`)을 그립니다. |
| 창을 좁히거나 다른 pane 탭이 앞에 있음 | pane이 배치되지 않거나 가려진 것을 감지하고, band가 5행 HUD로 펼쳐집니다. |
| 전체 화면이 아닌 보기 | pane을 열지 않습니다. 열린 pane이 입력창 위 블록으로 놓이면 닫고 band를 씁니다. |
| pane을 직접 닫음 | 다시 자동으로 열지 않습니다. `/pane-mod`로 다시 엽니다. |

### 힌트 줄 레이아웃 (`layout: hint`)

- band와 pane을 그리지 않고, 입력창 아래의 흐린 힌트 줄(`? for shortcuts`, `esc to interrupt` 등) 끝에 HUD를 한 줄로 붙입니다. 화면 공간을 거의 쓰지 않고 핵심 값만 볼 때 씁니다.
- 예: `? for shortcuts · ctx 42% · 5h 70% · Opus 5.5 xhigh · tasks 2/5 · subagents 1 · Bash`
- context 사용률, 5h 사용률, 모델과 effort, Claude의 작업(완료 수/전체), 실행 중인 서브에이전트 수, 메인 세션이 지금 실행 중인 도구 순서로 적습니다. 값이 없는 항목은 빼고, 줄이 터미널 폭을 넘으면 Claude Code가 끝을 자릅니다.
- `/pane-mod`로 pane을 열 수 있습니다. pane이 보이는 동안에는 pane이 HUD를 맡으므로 힌트 줄에는 붙이지 않습니다.
- band가 없으므로 스프라이트는 보이지 않습니다. 동작 소리와 승인 창 아래 한 줄은 다른 레이아웃과 같습니다.
- 힌트 줄에 덧붙인 내용은 터미널에서만 보입니다. Claude Code가 다른 화면에는 아직 그리지 않기 때문입니다.

pane의 카드:

| 카드 | 내용 |
|---|---|
| 첫 카드 (session, now) | pane 폭 전체를 쓰며, 오른쪽에 스프라이트를 담고 그 왼쪽에 내용을 위쪽부터 놓으며, 글자 영역은 스프라이트와 같은 높이를 차지합니다. 도구 행은 도구를 실행하지 않을 때도 자리를 비워 두므로, 도구 호출이 시작되거나 끝나도 행 위치와 카드 높이가 바뀌지 않습니다. `/rename`으로 지정한 세션 이름(굵게), 프로젝트(branch, linked worktree이면 `⎇` 표시), 권한 모드·턴 수·출력 스타일, 작업 상태(진행 중이면 노란 ` ● WORKING ` 배지와 턴 경과 시간), 메인 세션이 지금 실행 중인 도구와 대상(파일 이름, 명령 앞부분, 검색어 등)과 실행 시간. 테두리와 이름에는 `/color`로 고른 색이 입혀지고, 고르지 않았으면 테두리는 흐린 노랑입니다(아래 "세션 이름과 색" 참고). `sessionColor`로 색을 고정하면 `/color`와 관계없이 그 색을 씁니다. 세션 이름이 없고 session·now가 모두 꺼져 있으면 스프라이트만 담고, 스프라이트도 없으면 그리지 않습니다 |
| tasks | Claude의 작업 목록(`TaskCreated`·`TaskCompleted` 이벤트, `TaskUpdate`·`TodoWrite` 도구). 제목 옆에 완료 수(`1/3`)를 적고, 진행 중(`▶`, 진행형 문구), 대기(`○`), 완료(`✓`) 순서로 8개까지 보여 줍니다. 세션 로그와 함께 저장해 `claude -c`로 다시 열어도 남습니다. 작업이 없으면 카드도 없습니다. |
| 모델 카드 (model, usage, totals) | 테두리는 기본으로 Claude 주황(테마 키 `claude`)이며, `modelColor`로 바꿉니다. model: 모델과 effort 게이지(totals가 꺼져 있으면 세션 비용도). usage: context 게이지와 토큰 수/창 크기(`98k/200k`), 5h와 7d 게이지와 리셋까지 남은 시간, 지금 속도라면 **리셋 전에 5h 한도에 도달할 때만** `≈ 50m to the 5h limit`(최근 1시간의 5h 사용률 변화로 계산). totals: 세션 비용, 세션 전체의 입력·출력 토큰(모든 턴의 `usage` 합계, 서브에이전트 포함)과 캐시에서 읽은 비율. 합계는 세션 로그와 함께 저장합니다 |
| subagents | 서브에이전트 목록. 제목 옆에 상태별 수와 전체 수(`2 running · 1 idle · 3`)를 적습니다. 행마다 이름(이름이 없으면 타입)과 흐린 타입, 작업 설명, 경과 시간, 도구 호출 수, 지금 실행 중인 도구를 보여 줍니다(아래 "표시 항목과 출처" 참고) |
| context | md 파일(출처별), hooks, 도구, MCP(도구·서버 수), skills, slash commands를 두 줄로 보여 줍니다. 기본으로 꺼져 있습니다(`showContext`) |
| recent | 이 세션에서 최근에 쓴 skill(Skill 도구로 실행한 것)과 MCP 도구(`server:tool`)를 가장 최근에 쓴 것부터 각각 5개까지 보여 줍니다. skill은 `skills` 행에, MCP 도구는 `mcp` 행에 모으며, 폭이 좁으면 줄을 바꿉니다. 진행 중인 턴과 이 세션의 로그 줄에서 모으고, 서브에이전트가 쓴 것도 포함합니다. 쓴 것이 없으면 카드도 없습니다(`showRecent`) |
| log | 끝난 턴마다 한 줄: 시각, 결과(✓ 완료, ⏹ 중단, ⊘ 거절, ✗ 오류), 소요 시간, 프롬프트 앞부분, 한 일(파일 수정 수, bash, 읽기·검색, 서브에이전트, 실패한 호출 `err`, 거부된 호출 `denied`), 출력 토큰, 캐시 적중률. 최신 순으로 **최근 5줄**을 보여 줍니다. 로그 카드가 pane의 마지막 카드이면, 로그 위에서 마우스 휠을 굴릴 때 pane은 그대로 두고 로그만 한 줄씩 넘어갑니다(아래 "로그 스크롤" 참고). `▲ older` / `▼ newer` 버튼(클릭, 또는 pane에 포커스가 있을 때 `o` / `n` 키)은 5줄씩 넘깁니다. 줄이 5줄보다 많으면 제목 아래에 검색칸이 생깁니다(아래 "로그 검색" 참고). 줄 앞의 `▸`를 누르면 그 줄 아래에 상세 내용이 펼쳐집니다(아래 "로그 상세" 참고). 세션마다 최근 50턴(`logTurns`)을 보관합니다(아래 "로그 보관" 참고). |

### 로그 스크롤

- mod에는 pane 안에 따로 스크롤되는 영역을 만드는 기능이 없습니다(`Box`의 `overflow`는 `visible`/`hidden`뿐입니다). 대신 pane이 스크롤되기 직전에 오는 `ui.scroll` 이벤트를 받아, 휠이 로그 위에 있으면 pane을 움직이지 않고 로그만 넘깁니다. 엔진 문서가 "헤더 아래에 자기 행을 그리는 훅"에 권하는 방식입니다.
- 휠이 로그 위에 있는지는 이벤트의 포인터 행(`pointer.row`)과 pane의 스크롤 위치로 판단합니다. 로그 카드는 행마다 한 줄로 그려서(상세의 프롬프트도 mod가 칸 수로 직접 줄을 나눕니다) 테두리 두 줄을 포함해 차지하는 행 수를 정확히 압니다. 기본 순서에서는 로그 카드가 pane의 마지막 카드이므로, pane 맨 아래에서 그 행 수만큼이 로그 영역입니다.
- **`paneOrder`에서 `log`를 마지막이 아닌 자리에 두면 휠은 로그를 넘기지 않습니다.** 로그 아래에 놓인 카드는 pane 폭에 따라 줄을 바꾸므로 높이를 정확히 알 수 없고, 그래서 로그 영역의 위치도 알 수 없기 때문입니다. 이때 휠은 로그 위에서도 언제나 pane을 스크롤하며, 로그는 `▲ older` / `▼ newer` 버튼(또는 pane에 포커스가 있을 때 `o` / `n` 키)으로 5줄씩 넘깁니다.
- 로그 위에서 아래로 굴리면 오래된 줄로, 위로 굴리면 최신 줄로 갑니다. 로그가 더 갈 곳이 없으면(맨 위나 맨 끝) 그 휠은 pane 스크롤로 넘어갑니다. 키보드 스크롤과 로그 밖의 휠은 지금처럼 pane을 스크롤합니다.
- **상세를 펼친 동안에는 휠이 로그 줄을 넘기지 않습니다.** 보이는 줄 중 하나가 펼쳐져 있으면 휠은 pane만 스크롤하므로, 긴 상세도 끝까지 읽을 수 있고 끝에 닿아도 목록이 바뀌지 않습니다. 목록을 넘기려면 상세를 닫거나 `▲ older` / `▼ newer` 버튼을 씁니다.
- 펼친 줄이 없어도 로그 카드가 휠 방향으로 화면 밖에 걸쳐 있으면, 로그 줄을 넘기기 전에 pane을 먼저 스크롤해서 로그 카드를 보여 줍니다.

### 로그 검색

- 로그가 5줄보다 많으면 log 카드의 제목 아래에 `find` 입력칸이 생깁니다. 입력칸을 클릭하거나, pane에 포커스가 있을 때 `s` 키를 누르면 입력칸으로 갑니다.
- 입력하는 대로, 적은 단어가 모두 들어간 줄만 최신 순으로 보여 줍니다. 대소문자는 가리지 않으며, 공백으로 나눈 단어가 모두 있어야 합니다(예: `login test`).
- 프롬프트, 수정한 파일 이름, 실행한 bash 명령, 도구 이름, skill, MCP 도구, 서브에이전트의 종류와 작업 설명, 실패한 호출의 내용에서 찾습니다.
- 제목에는 `1–5 of 12 found`처럼 찾은 줄 수를 적습니다. 찾은 줄이 없으면 제목에 `none found`라고 적고, 그 아래에 찾지 못한 검색어를 한 줄로 알립니다.
- 검색하는 동안에는 버튼 행에 `x: clear`가 생기며, 누르면(클릭, 또는 `x` 키) 검색어를 지우고 모든 줄로 돌아갑니다. 입력칸에 포커스가 있으면 글자 키가 모두 입력칸으로 가므로, 단축키는 Tab으로 입력칸을 벗어난 뒤에 씁니다. pane은 Esc를 누르면 닫히므로, 입력칸을 벗어날 때는 Esc 대신 Tab을 씁니다.
- 지금 불러온 줄(`logTurns`만큼, `0`이면 모든 줄)에서 찾습니다. 검색어는 세션 동안 유지되며, `/clear`, `/resume`을 실행하면 비워집니다.

### 로그 상세

- 줄 앞의 `▸`를 클릭하거나, pane에 포커스를 둔 뒤 Tab으로 옮겨 Enter를 누르면 그 줄 아래에 상세 내용이 펼쳐지고 표시가 `▾`로 바뀝니다. 한 번에 한 줄만 펼치며, 같은 표시를 다시 누르면 접힙니다.
- 펼친 내용은 잘라 내지 않고 줄을 바꿔 보여 줍니다.
  - 끝난 날짜와 시각, 결과(answered / stopped / refused / failed), 소요 시간
  - 프롬프트 전문(태그를 빼고 줄바꿈을 살린 최대 300자)
  - `edited`: 수정한 파일 이름(최대 8개, 넘으면 `+N`)
  - `bash`: 실행한 명령의 첫 줄(중복을 빼고 최대 5개, 각 80자)
  - `tools`: 메인 세션이 도구별로 호출한 횟수입니다. 많이 쓴 도구부터 적고, 도구 10개까지 이름을 적은 뒤 나머지 도구의 호출은 `(other)`로 합칩니다. MCP 도구는 `server:tool`로 적습니다.
  - `skills`: Skill 도구로 실행한 skill 이름(중복을 빼고 처음 실행한 순서로 최대 6개)
  - `mcp`: 호출한 MCP 도구(`server:tool`, 중복을 빼고 처음 호출한 순서로 최대 6개). `skills`와 `mcp`에는 서브에이전트가 쓴 것도 들어갑니다.
  - `subagents`: 턴 동안 시작된 서브에이전트(최대 6개)마다 한 줄씩 종류, 작업 설명, 끝난 방식(done / stopped / refused / failed / running), 시작부터 끝날 때까지 걸린 시간을 적습니다. 턴이 끝날 때 아직 실행 중이던 서브에이전트(background 실행 등)는 `running`으로 저장하고, 그 서브에이전트가 끝나면 같은 줄에 결과와 시간을 다시 씁니다.
  - `errors`: 실패한 도구 호출(최대 5개)마다 한 줄씩 도구, 서브에이전트의 호출이면 `(subagent)` 표시, 오류 메시지의 첫 줄(태그를 빼고 최대 100자)을 적습니다. 사용자가 중단한 호출은 실패로 세지 않습니다.
  - `asked`: 승인 창이 열린 호출(최대 5개)의 도구와 대상(파일 이름, 명령 앞부분 등)입니다. `alerts` 설정을 꺼도 기록합니다.
  - `denied`: 거부된 호출(`PermissionDenied`, 최대 5개)의 도구와 대상입니다.
  - `done`: 한 일의 개수(실패한 호출 `err`, 거부된 호출 `denied` 포함), 출력 토큰, 캐시 적중률
  - `c: copy prompt`: 프롬프트를 클립보드로 복사합니다(클릭, 또는 pane에 포커스가 있을 때 `c` 키).
- 내용이 없는 항목은 그리지 않습니다. 실패한 호출과 거부된 호출은 HUD에 따로 세지 않고, 이렇게 턴의 로그에만 남깁니다. 오류는 transcript에도 이미 표시되기 때문입니다.
- 펼칠 때 상세 내용이 보이도록 pane을 스크롤합니다.

### 로그 파일 열기

- log 섹션 아래의 `f: open file`을 클릭하거나, pane에 포커스가 있을 때 `f` 키를 누르면 이 세션의 로그를 Markdown 파일로 쓰고 바로 엽니다.
- 파일 위치는 `~/.claude/plugins/data/pane-mod-pane-mod/logs/<세션 ID>.md`입니다. Claude Code가 이 플러그인에 정해 주는 데이터 폴더(`CLAUDE_PLUGIN_DATA`)이므로, 플러그인을 삭제하면 함께 지워집니다. `CLAUDE_CONFIG_DIR`을 쓰면 그 아래에 둡니다. 이 Markdown 파일은 아래 "로그 보관"의 한도와 관계없이 남습니다.
- 파일 맨 위에는 세션 이름, 프로젝트(branch), 세션 ID, 작성 시각을 적습니다. 그 아래에는 턴마다 제목(날짜 · 결과 · 소요 시간)을 달고, 프롬프트를 인용문(`>`)으로, 로그 상세의 항목(수정 파일, 명령, 도구별 호출 수, skill, MCP 도구, 서브에이전트, 실패한 호출, 승인 요청, 거부된 호출, 개수)을 목록으로 최신 순으로 적습니다. 서브에이전트와 실패한 호출은 한 줄에 하나씩 하위 목록으로 적습니다.
- 파일은 macOS의 `open`으로 엽니다(그 확장자의 기본 앱). `open`이 없으면 `xdg-open`을 씁니다. 열지 못해도 파일은 그 경로에 남습니다.
- 파일은 누를 때만 씁니다. 누를 때마다 그 시점의 로그로 다시 씁니다.

### 로그 보관

- 로그는 **세션 ID별로** 플러그인 데이터 폴더의 JSON 파일에 저장합니다. 위치는 `~/.claude/plugins/data/pane-mod-pane-mod/sessions/<세션 ID>.json`이며, `CLAUDE_PLUGIN_DATA`가 가리키는 폴더(`CLAUDE_CONFIG_DIR`을 쓰면 그 아래)입니다. 턴이 끝날 때마다 저장하고, `/color`로 고른 세션 색, Claude의 작업 목록, 토큰 합계도 같은 파일에 함께 저장합니다.
- 턴이 진행되는 동안 세션이 끝나면(터미널 창을 닫거나 프로세스가 종료 신호를 받으면) 그 턴을 끝난 시각까지의 소요 시간과 함께 `⏹ 중단`으로 저장합니다. 이때는 종료가 늦어지지 않도록 보관 한도를 넘은 파일을 지우지 않고, 다음에 저장할 때 지웁니다.
- `claude -c`나 `claude --resume`으로 같은 세션을 이어 가면 세션 ID가 같으므로 로그가 복구됩니다. 다른 세션과는 공유되지 않습니다. `--fork-session`으로 갈라져 나온 세션은 새 ID이므로 빈 로그로 시작합니다.
- 보관 한도는 아래 세 설정으로 정합니다. 각 설정에 `0`을 적으면 그 한도를 두지 않으므로, 셋 다 `0`이면 모든 세션의 모든 턴을 기간 제한 없이 보관합니다.

  | 설정 | 기본값 | 한도 |
  |---|---|---|
  | `logTurns` | `50` | 세션마다 보관하는 최근 턴 수입니다. 넘으면 오래된 턴부터 지웁니다. 1부터 4까지는 5로 처리합니다. |
  | `logSessions` | `30` | 로그를 보관하는 세션 수입니다. 가장 최근에 저장한 세션부터 남깁니다. |
  | `logDays` | `14` | 마지막으로 저장한 뒤 로그를 보관하는 날수입니다. |

- 세션 수와 날수의 한도는 로그를 저장할 때마다 적용합니다. 폴더의 파일 목록(`$.fs.list`)에서 각 세션 파일의 수정 시각을 마지막 저장 시각으로 보고, 한도를 넘은 세션의 파일을 `/bin/rm`으로 지웁니다. 지금 세션의 파일은 지우지 않으며, 로그 파일의 이름 형식(`<세션 ID>.json`, `<세션 ID>.<번호>.json`)이 아닌 파일은 건드리지 않습니다.
- `rm`을 실행할 수 없는 환경(외부 프로그램을 실행하지 않는 Desktop 앱 등)에서는 지울 파일의 내용을 비웁니다. 비운 파일은 로그가 없는 것으로 보고, 나중에 `rm`을 실행할 수 있는 세션이 저장할 때 지웁니다. `$.fs`에는 파일을 지우는 메서드가 없기 때문입니다.
- Claude Code는 파일 하나를 4 MiB까지만 읽고 쓸 수 있게 제한합니다. 그래서 `<세션 ID>.json`에는 최근 200줄까지만 담고, 로그가 200줄을 넘으면 오래된 줄을 200줄씩 `<세션 ID>.1.json`, `<세션 ID>.2.json`, …에 나누어 봉인합니다(1이 가장 오래된 묶음입니다). 봉인한 파일은 내용이 바뀌지 않는 한 다시 쓰지 않습니다. `logTurns`가 200 이하이면 세션마다 파일이 하나만 생깁니다.
- 모든 턴을 보관하다가 `logTurns`를 다시 정하면, 다음에 그 세션을 불러올 때 최근 턴만 읽고, 저장할 때 필요 없어진 봉인 파일을 지웁니다.
- 로그를 플러그인 저장소(`$.store`)가 아니라 파일에 두는 이유는 용량입니다. 저장소는 모든 키를 합쳐 4 MiB까지만 담을 수 있어서, 턴과 세션을 제한 없이 보관하면 금방 넘칩니다.
- 한 줄에 담는 항목은 개수와 길이를 모두 제한합니다. 저장하는 문자열에서는 제어 문자를 빼므로, 글자 하나는 JSON에서 최대 3바이트(한글 등)를 차지합니다.

  | 항목 | 최대 개수 | 문자열 최대 길이 |
  |---|---|---|
  | 프롬프트 | 1 | 300자 |
  | 수정한 파일 이름 | 8 | 60자 |
  | 명령 | 5 | 80자 |
  | 도구별 호출 수 | 도구 10개와 `(other)` | 이름 64자 |
  | skill, MCP 도구 | 각 6 | 64자 |
  | 서브에이전트 | 6 | 종류 64자, 작업 설명 60자 |
  | 실패한 호출 | 5 | 도구 64자, 오류 100자 |
  | 승인 요청, 거부된 호출 | 각 5 | 도구 64자, 대상 40자 |

- 이 제한으로 계산한 크기는 다음과 같습니다. 최악의 경우는 모든 항목을 최대 개수와 최대 길이로 채우고 모든 글자가 3바이트인 경우이며, 이때 한 줄은 약 17KiB입니다. 보통의 줄(프롬프트 한 문장, 파일 몇 개, 도구 대여섯 종류)은 약 0.6KiB입니다.

  | 설정 | 세션 하나 (최악) | 전체 (최악) | 전체 (보통의 줄) |
  |---|---|---|---|
  | 기본값 (50턴, 30세션) | 약 0.8MiB | 약 24MiB | 약 0.9MiB |
  | 200턴, 100세션 | 약 3.2MiB | 약 323MiB | 약 11MiB |
  | 제한 없음 (`0`) | 200턴마다 약 3.2MiB | 세션 수에 비례 | 세션 하나의 200턴마다 약 0.12MiB |

- 파일 하나는 최악의 경우에도 약 3.2MiB이므로 4 MiB 제한을 넘지 않습니다. 폴더 전체의 용량에는 한도가 없으며, 디스크가 허용하는 만큼 보관합니다. 파일을 쓰지 못하면(디스크가 가득 찼거나, 다른 플러그인의 `fs.*` hook이 막은 경우 등) 그 저장만 건너뛰고, pane에는 이번 세션의 줄이 모두 남습니다. 어느 경우에도 오류가 hook 밖으로 나가지 않습니다.
- 모든 턴을 보관하면 pane의 log 카드가 세션의 모든 줄을 메모리에 두고 HUD를 갱신할 때마다 함께 비교합니다. 수천 턴이 넘는 세션에서는 HUD 갱신이 무거워질 수 있습니다.

### 세션 이름과 색

- 세션 이름은 `/rename`으로 지정한 이름만 씁니다. Claude Code가 자동으로 만드는 제목은 쓰지 않습니다. 세션을 시작하거나 이어 갈 때(`classic.SessionStart`), 프롬프트를 보낼 때(`classic.UserPromptSubmit`) 훅 입력의 `session_title`로 읽고, `/rename`을 실행하면 그 출력 행(`Session renamed to: …`)을 읽어 바로 바꿉니다.
- 색은 `/color`의 출력 행(`Session color set to: …`, `Session color reset to default`)을 읽어 바꿉니다. 색은 어떤 훅 입력에도 실려 오지 않으므로, 세션 로그와 함께 저장해 두었다가 `claude -c` / `--resume` 때 되살립니다. 그래서 pane-mod를 설치하기 전에 고른 색은 `/color`를 한 번 다시 실행해야 표시됩니다.
- 색은 pane 첫 카드의 테두리와 세션 이름에 칠합니다. Claude Code 테마의 세션 색 키(`red_FOR_SUBAGENTS_ONLY` 등)를 쓰므로, 입력창 테두리와 같은 색이 테마(다크, 라이트, ANSI)에 맞게 나옵니다.
- `sessionColor` 설정에 테마 키나 `#rrggbb` 형식의 색을 적으면, 첫 카드의 테두리와 세션 이름은 `/color`와 관계없이 그 색으로 그려집니다. 이때도 `/color`로 고른 색은 세션 로그와 함께 저장되므로, 설정을 `auto`로 되돌리면 다시 표시됩니다.

## 알림

pane-mod는 toast나 소리로 사용자를 부르지 않습니다. 승인 창, 질문 창, context 부족 경고는 Claude Code가 이미 보여 주고, 자리를 비웠을 때의 알림은 터미널(예: Orca의 알림)이나 Claude Code의 알림 설정이 맡는 편이 중복되지 않기 때문입니다. 대신 Claude Code가 보여 주지 않는 정보만 승인 창 아래에 한 줄로 붙입니다(`alerts` 설정, 기본 켜짐).

- **승인 창 아래 한 줄**: 도구 실행 승인 창이 열리면(`classic.PermissionRequest`. 설정 훅이 자동으로 결정한 경우는 제외) 그 선택지 아래에 `pane-mod · waiting since 14:09 · ▲ context 88%`처럼 한 줄을 붙입니다(`$.ui.notice`). 언제부터 기다렸는지와, 그때 떠 있는 한도 경고를 적습니다. 엔진은 승인 창이 열려 있지 않은 호출에는 이 줄을 받지 않고 거부 여부도 알려 주지 않으므로, 창이 열린 직후와 약 6초 뒤의 `permission_prompt` 알림 때 두 번 붙입니다. 호출이 끝나면 엔진이 지웁니다.
- **한도 경고**: 아래 경고는 1분 동안 떠 있으며, 그동안 승인 창이 열려 있으면 그 줄에 함께 적습니다.

  | 경고 | 언제 |
  |---|---|
  | `▲ context 85%` | context가 80%, 90%에 닿을 때. Claude Code의 자체 경고보다 이른 단계입니다 |
  | `▲ 5h 82% · resets in 1h20m` | 5h 사용률이 80%, 90%에 닿을 때 |
  | `▲ 5h limit in ~50m at this pace` | 지금 속도라면 리셋 전에 5h 한도에 닿을 때(30분에 한 번까지) |

- **경고 기준**: 같은 기준(80%, 90%)은 한 번만 경고합니다. 사용률이 그 아래로 내려가면(compact, 새 5h 구간) 다시 경고할 수 있습니다. 한 번에 두 기준을 넘으면 높은 쪽 하나만 경고합니다.
- **승인 대기가 끝나는 때**: 그 호출이 실행되기 시작할 때(긴 명령의 "ctrl+b to run in background" 안내), 끝나거나 거부될 때, 메인 턴이 끝날 때입니다.

### pace(5h 한도 도달 예측)를 계산하는 방법

모델이 판단하는 값이 아닙니다. 엔진이 알려 주는 숫자로 mod가 직접 계산합니다.

1. 2초마다 `$.session.usage()`의 `rateLimits`에서 5h 사용률(`percentUsed`)을 읽습니다. 이 값은 API 응답의 사용량 정보를 Claude Code가 전달한 것입니다.
2. 값이 바뀔 때마다 (시각, 사용률)을 기록하고, 최근 60분 기록만 남깁니다. 사용률이 내려가면 새 5h 구간이 시작된 것으로 보고 기록을 비웁니다.
3. 가장 오래된 기록과 지금 값의 차이로 속도를 구합니다. 예를 들어 10분 동안 40%에서 50%가 되었다면 속도는 분당 1%입니다.
4. 남은 비율을 속도로 나눠 한도까지 남은 시간을 구합니다. 앞의 예에서는 남은 50%를 분당 1%로 나눠 50분입니다.
5. 기록 간격이 5분 미만이거나 상승폭이 1% 미만이면 예측하지 않습니다. 예측한 시간이 리셋까지 남은 시간보다 길면(리셋이 먼저 오면) 표시하지 않습니다.

pane이 붙는 쪽(오른쪽)은 Claude Code가 정합니다. mod가 왼쪽을 고를 방법은 없습니다. 요청하지 않은 pane은 터미널 폭 144칸부터 배치되고, 사용자가 한 번 직접 열면 110칸부터 배치됩니다.

## 스프라이트 동작

| Claude 상태 | 동작 |
|---|---|
| 턴 사이 | `idle` 반복 |
| 모델 턴 진행 중 (`turn.start`부터 `turn.complete`까지. 스킬처럼 모델 턴을 여는 슬래시 명령 포함) | `working` 반복 |
| 모델 턴을 열지 않는 단발 명령 (`/effort`, `/reload-plugins` 등) | `idle` 유지 |
| 턴 종료 (완료, 중단, 거절, API 오류) | 바로 `idle`로 전환 |

`complete` 동작은 지금 꺼져 있습니다. `hooks/register.tsx`의 `IS_CHEERING`을 `true`로 바꾸면, `reason: 'answer'`로 끝난 턴에서 `complete`를 한 번 재생하고 마지막 프레임을 유지하다가 3초 뒤 `idle`로 돌아갑니다. 앞으로 추가할 수 있는 상태와 필요한 스프라이트는 [docs/sprite-states.md](docs/sprite-states.md)에 정리했습니다.

모든 프레임은 80ms 간격(12.5fps)으로 재생됩니다. 세 동작의 프레임을 같은 크기로, 같은 기준 영역에 맞춰 잘라 두면 동작이 바뀌어도 크기와 위치가 흔들리지 않습니다. 제작 규격은 [docs/sprite-states.md](docs/sprite-states.md)에 있습니다.

### 스프라이트와 소리 파일

스프라이트 프레임과 소리 파일은 저장소에 들어 있지 않습니다. 직접 준비한 폴더를 `spriteDir`, `soundDir`로 지정하면, mod는 세션이 시작될 때 아래 구조로 폴더를 읽고 찾은 파일만 씁니다.

```text
<스프라이트 폴더>/            # spriteDir, 비워 두면 플러그인 폴더의 assets/
├── idle/     *.png          # 턴 사이
├── working/  *.png          # 모델 턴 진행 중
└── complete/ *.png          # 턴 완료 (IS_CHEERING을 켰을 때만)
<소리 폴더>/                  # soundDir, 비워 두면 플러그인 폴더의 assets/sounds/
├── working/  *.caf, *.wav, … # 모델 턴 시작
└── idle/     …               # 턴 종료
```

- **프레임**: 동작 폴더의 PNG 파일을 이름 순서로 재생합니다. 프레임 수는 폴더에 든 파일 수로 정해지므로 `frame_001.png`, `frame_002.png`처럼 번호를 0으로 채워 이름 순서와 재생 순서를 맞춥니다. 크기와 변환 방법은 [docs/sprite-states.md](docs/sprite-states.md)의 "스프라이트 제작 규격"을 따릅니다.
- **소리**: 상태 폴더의 `.caf`, `.wav`, `.aif`, `.aiff`, `.mp3`, `.m4a`, `.aac` 파일 중 하나를 무작위로 재생하며, 새 소리가 시작되면 재생 중이던 소리를 멈춥니다. `soundDir`로 지정한 폴더의 파일은 mod가 한 번 읽어서 데이터로 재생합니다.
- **파일이 없을 때**: 프레임이 없는 동작은 `idle`의 프레임을 빌려 쓰고, `idle`에도 없으면 다른 동작의 프레임을 씁니다. 어느 폴더에도 프레임이 없으면 스프라이트와 그 여백을 생략하고, 그 자리를 글자 HUD가 씁니다. 소리 파일이 없는 상태에서는 소리를 내지 않습니다. 폴더 목록에는 있지만 읽거나 재생할 수 없는 파일은 그 세션에서 건너뜁니다. 어느 경우에도 오류를 내지 않습니다.
- **파일을 바꾼 뒤**: 폴더는 세션이 시작될 때(그리고 `/reload-plugins`로 다시 읽을 때) 한 번 읽습니다. 파일을 넣거나 뺀 뒤에는 `/reload-plugins`를 실행합니다.
- **플러그인 폴더의 `assets/`**: 저장소를 clone해서 쓰는 경우에는 설정 없이 clone한 폴더의 `assets/`에 파일을 넣어도 됩니다. 이 폴더는 `.gitignore`에 들어 있어서 커밋되지 않습니다.

### 사례: 좋아하는 캐릭터를 스프라이트로

맨 위의 데모는 좋아하는 캐릭터의 idle(턴 사이)과 working(모델 턴 진행 중) 상태를 프레임으로 뽑아 `spriteDir`로 지정하고, 질문 하나를 처리하는 모습을 1.5배속으로 녹화한 것입니다. 질문을 보내면 pane의 스프라이트가 working 동작으로 바뀌고 ` ● WORKING ` 배지와 경과 시간이 나타납니다. 답이 끝나면 idle 동작으로 돌아오고, log 카드에 그 턴이 한 줄 남습니다. 폴더 구성과 지정하는 명령은 "빠른 시작"에 있습니다.

- 스프라이트가 그려지는 것은 Ghostty와 cmux에서 확인했습니다.
- Orca에서는 현재 버전(1.4.221) 기준으로 그려지지 않습니다. 이때 pane-mod는 스프라이트 자리를 비우고 글자 HUD만 표시합니다(위 "요구 사항" 참고).
- 데모의 캐릭터는 예시입니다. 지적 재산권은 원래의 권리자에게 있으며, 그 스프라이트와 소리는 개인 용도로만 쓰고 배포하지 않습니다(아래 "라이선스" 참고).
- 폴더는 플러그인 데이터 폴더(`~/.claude/plugins/data/…`) 밖에 두는 것이 좋습니다. 데이터 폴더는 플러그인을 삭제할 때 함께 지워집니다.

## 표시 항목과 출처

| 행 | 항목 | 엔진 API |
|---|---|---|
| 1 | 프로젝트(branch, linked worktree이면 `⎇` 표시) | `$.session.cwd()`, `.git/HEAD`(`$.fs`) |
| 2 | 모델(반전 배지, `Opus 5.5` 같은 표시 이름), effort(5단계 게이지), 세션 비용 | `$.session.model()`, `turn.step`의 `effort`, `/effort` 출력, 설정의 `modelSettings`·`effortLevel`, `usage().cost` |
| 3 | 컨텍스트 %, 5시간·주간 한도 %와 리셋까지 남은 시간 | `usage().context`, `usage().rateLimits` |
| 4 | md 파일(출처별), hooks, 기본 도구·MCP(서버 수)·skills·slash commands | `usage({ breakdown: 'summary' })`, `$.settings.read()`, `$.tool.list()` |
| 5 | 권한 모드, 작업 상태(진행 중이면 노란 배지와 경과 시간), 지금 실행 중인 도구, 턴 수, 출력 스타일 | `classic.UserPromptSubmit`, `AbovePrompt.isWorking`, `$.session.turns()`, `prompt.compose` |
| 6~ | 서브에이전트(`agents` 설정: 상태별 개수 한 줄, 또는 실행 중인 것 먼저 한 줄씩. 끝난 것은 30초 동안 셈) | `$.agent.list()`, `tool.call`의 `agentId` |

- effort는 5단계 게이지로 표시합니다. low `▰▱▱▱▱`(회색), medium `▰▰▱▱▱`(초록), high `▰▰▰▱▱`(노랑), xhigh `▰▰▰▰▱`(주황), max `▰▰▰▰▰`(빨강, 굵게)입니다. 값은 메인 세션의 모델 요청(`turn.step`)이 실어 보내는 값을 가장 먼저 쓰고, `/effort`로 바꾸면 transcript에 남는 그 출력 행(`Set effort level to …`)을 읽어 바로 바꿉니다. 메뉴에서 고르면 명령 결과에는 문구가 담기지 않기 때문입니다. `max`는 설정 파일에 저장되지 않으므로 이 행이 유일한 단서입니다. 첫 요청 전에는 `CLAUDE_CODE_EFFORT_LEVEL`, 설정의 `modelSettings[모델].effortLevel`, 최상위 `effortLevel` 순서로 추정합니다. `/model`로 모델을 바꾸면 새 모델 기준으로 다시 추정합니다. 숫자 예산이면 `N tokens`로 표시합니다.
- 모델은 Claude Code의 메뉴처럼 `Opus 5.5`, `Fable 5.1`, `Sonnet 3.5` 같은 표시 이름으로 보여 줍니다. 모델 ID(`claude-opus-5-5[1m]`, `claude-3-5-sonnet-20241022`, `us.anthropic.claude-sonnet-5-5` 등)에서 계열과 버전을 읽고, 날짜·제공자 접두사·context 표시는 뺍니다. 계열이나 형식을 알 수 없는 ID(이 mod보다 새로운 모델 등)는 받은 그대로 보여 줍니다.
- 사용량 막대(ctx, 5h, 7d)는 모두 10칸의 `▰▱`이고, 채워진 칸과 숫자는 사용률에 따라 색이 바뀝니다. 0~59%는 초록, 60~89%는 노랑, 90% 이상은 빨강입니다. 빈칸은 테마의 회색(`subtle`)으로 칠합니다. `▰▱`는 칸 높이보다 낮아서, 위아래 줄의 막대가 서로 붙어 보이지 않습니다. effort 게이지를 포함한 모든 게이지의 문자는 `barFilled`(채워진 칸)와 `barEmpty`(빈칸)로 바꿀 수 있으며, 색은 바뀌지 않습니다.
- 사용량·턴 수·서브에이전트는 2초마다, branch·hooks·tools·md 파일은 15초마다 읽습니다. 메인 턴이 끝날 때도 한 번 더 읽습니다.
- branch는 `.git/HEAD`에서 읽습니다. linked worktree(`git worktree add`로 만든 작업 폴더나 Claude Code의 worktree)에서는 `.git` 파일이 가리키는 그 worktree의 HEAD를 읽고, branch 뒤에 `⎇`를 붙여 메인 체크아웃이 아니라는 것을 알립니다. worktree의 이름은 보통 그 폴더의 이름과 같고 프로젝트 자리에 이미 나오므로 따로 적지 않습니다.
- 서브에이전트에 `Agent({ name })`으로 이름을 붙였으면 이름을 먼저 보여 주고 타입은 흐리게 뒤에 붙입니다. 일을 마치고 메시지를 기다리는 teammate는 running이 아니라 `idle`로 세고, idle인 동안에는 경과 시간을 멈춥니다. 자기 터미널에서 도는 teammate의 도구 호출은 이 세션의 hook을 거치지 않으므로, 도구 호출 수가 0이면 적지 않습니다. 입력창 아래 Claude Code agent panel의 진행 요약(`label`)은 mod가 받는 정보에 없으므로, pane-mod는 서브에이전트를 띄울 때 받은 작업 설명을 보여 줍니다.
- 세션 경과 시간과 시간당 비용은 표시하지 않습니다. 세션을 켜 둔 채 자리를 비우면 시간당 비용이 실제 사용과 관계없이 떨어지기 때문입니다. 비용은 세션 총액만 보여 줍니다.
- 요금제 이름(Pro/Max)은 표시하지 않습니다. 엔진이 이 값을 제공하지 않고, 이 mod는 인증 정보를 읽지 않기 때문입니다.
- 권한 모드는 프롬프트를 보낼 때 갱신됩니다. 첫 프롬프트를 보내기 전에는 `mode --`로 표시됩니다.

## 이 mod가 컴퓨터에서 하는 일

- 네트워크 요청은 없습니다(`$.http`를 호출하지 않습니다). 외부 프로그램은 두 경우에만 실행합니다. log의 `f: open file`을 누르면 로그 Markdown 파일을 엽니다(`$.process.run(['/usr/bin/open', 로그 파일])`, 없으면 `xdg-open`). 로그를 저장할 때 보관 한도를 넘은 로그 파일이 있으면 `/bin/rm -f -- <파일들>`로 지웁니다. 지우는 대상은 데이터 폴더의 `sessions/`에 있는 로그 파일뿐입니다. `claude plugin validate .`의 `calls:` 목록에서 `$.process.run (via openLogFile, removeKept)`으로 확인할 수 있습니다.
- 슬래시 명령의 출력 행(`session.append`의 `door: 'command'`)을 읽지만, `/effort`의 레벨 문구, `/rename`의 이름 문구, `/color`의 색 문구만 찾고 다른 내용은 쓰지 않습니다.
- 승인 창 아래 한 줄과 작업 로그를 위해 설정 훅 이벤트(`PermissionRequest`, `Notification`, `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`)를 받지만, 결정을 바꾸지 않고 그대로 넘깁니다.
- 파일 읽기는 `.git` 경로 탐색과 `HEAD` 읽기, 스프라이트·소리 폴더의 파일 목록 읽기(`$.fs.list`), `png` 소스를 쓸 때의 스프라이트 PNG 읽기, `soundDir`로 지정한 폴더의 소리 파일 읽기, 보관한 로그 파일과 그 폴더의 목록 읽기뿐입니다. 파일 쓰기는 턴이 끝날 때마다(그리고 턴이 진행되는 동안 세션이 끝날 때) 세션의 로그 파일을 쓰는 것, `f: open file`을 누를 때 로그 Markdown 파일을 쓰는 것, `rm`을 실행할 수 없을 때 지울 로그 파일을 비우는 것뿐입니다.
- 작업 로그를 플러그인 데이터 폴더의 `sessions/`에 세션별 JSON 파일로 저장합니다(위 "로그 보관" 참고). 여기에는 **각 턴의 프롬프트(태그를 뺀 최대 300자)**, **수정한 파일 이름과 실행한 명령의 첫 줄**, **실패한 도구 호출의 오류 메시지 첫 줄(최대 100자)**, **승인 창이 열리거나 거부된 호출의 대상(파일 이름, 명령 앞부분 등)**, 도구별 호출 수, skill과 MCP 도구의 이름, 서브에이전트의 종류와 작업 설명, 시각, 소요 시간, 도구 사용 수, 출력 토큰, 캐시 적중률, 세션 색, 작업 목록, 토큰 합계가 들어갑니다. 외부로 보내지는 않습니다.
- 로그 상세의 `copy prompt`를 누르면 그 프롬프트를 클립보드에 씁니다(`$.ui.copy`). 누르지 않으면 클립보드를 건드리지 않습니다.
- Ghostty와 kitty에서는 터미널이 스프라이트 PNG를 직접 읽습니다(`Image`의 `file` 소스). 이미지 데이터가 엔진을 거치지 않습니다.
- 그 밖의 터미널에서는 mod가 PNG 파일을 한 번씩 읽어 데이터로 보냅니다(`png` 소스). 앱 안에서 그려지는 터미널은 파일 경로를 열지 못할 수 있기 때문입니다. 읽은 데이터는 메모리에 보관하므로 같은 프레임을 다시 읽지 않습니다.
- 엔진이 그림 대신 `alt`를 그렸다고 알려 오면(blit 거부), 파일 경로를 읽지 못한 경우에는 데이터 방식으로 바꾸고, 그림 자체를 그릴 수 없는 터미널이면 스프라이트를 숨깁니다.
- 터미널을 판단하려고 환경 변수 `TERM_PROGRAM`, `GHOSTTY_RESOURCES_DIR`, `KITTY_WINDOW_ID`를 읽고, effort를 추정하려고 `CLAUDE_CODE_EFFORT_LEVEL`을 읽습니다. 로그를 보관하고 Markdown 파일을 쓸 위치를 정하려고 `CLAUDE_PLUGIN_DATA`, `CLAUDE_CONFIG_DIR`, `HOME`을 읽고, `spriteDir`·`soundDir`의 `~`를 풀려고 `HOME`을 읽습니다.

## 개발

`.claude-plugin/types/`는 Claude Code가 mod를 처음 로드할 때 만들어 줍니다. 처음에는 `claude --plugin-dir .`로 한 번 실행했다가 종료한 뒤 아래 검사를 실행하세요.

```
tsc -p . --noUnusedLocals
claude plugin validate .
claude plugin test .
```

- 타입 검사에는 `target: es2023`을 지원하는 TypeScript가 필요합니다. 5.2.2는 이 target을 거부했고, 6.0.3에서 검사를 통과했습니다.
- `$`를 인자로 받는 함수는 반드시 파일 최상위에 선언해야 합니다. 엔진이 소스를 정적으로 분석해서 `$` 호출을 추적하기 때문입니다.
